#### R10. 증권사별 API 지원 현황은 어떤가

- **찾은 것:** 한 개발업체 블로그 비교에 따르면 KIS는 REST이고 맥·리눅스에서도 쓸 수 있으며 해외주식 5개국을 지원(O). 키움은 옛 방식이 윈도우 전용이고 새 REST가 있으며 해외주식은 X로 표기(다른 글은 REST에서 미국주식을 지원한다고 해서 자료끼리 어긋남). LS는 해외주식 X. 대신 CybosPlus는 윈도우 전용이고 해외는 "제한적". 토스·KB는 개인 개발자용 API를 공개. 신한·NH·미래에셋·삼성은 "각자 제공"한다고만 적혀 있고 세부 정보가 없음. 해외주식 잔고 조회가 명시된 곳은 KIS뿐.

### 0-5. 인터뷰에서 확인할 것

**개인 해외자산 환차손익 방향 (A안)**

1. 해외주식을 보유한 사람은 환율 영향을 지금 어디서, 어떻게 확인하는가. 증권사 앱 환차손익 화면(R2)을 보는가.

3. 알림이 필요하다면 어떤 상황에서 받고 싶은가. (환율 몇 % 이상 움직이면 등)
4. 주가 효과와 환율 효과를 나눠 보여 주는 도구를 써 본 적이 있는가.

**기업 결제 건별 환차 점검 방향 (B안)**

1. 결산 때 외화 결제 건의 환율을 어떻게 대조하는가. 도구와 걸리는 시간은 얼마인가.
2. 실제로 가장 자주 생기는 오류는 무엇인가. (환율 적용일 오류, 중복, 환율 누락 등)
3. 사내에서 쓰는 기준 환율은 무엇인가. (매매기준율, 고시환율 등)
4. 허용 오차는 어느 정도로 보는가. 이상치 기준을 어떻게 정하는가.

**해외결제 비용 방향 (확장 후보)**

1. 해외결제 후 청구액이 승인 문자 금액과 달랐던 경험이 있는가.
2. 원화결제 차단을 설정해 두었는가. 알고 있었는가.

**증권 정보 해설 방향 (10절)**

1. 증권 뉴스나 공시를 볼 때 이해가 안 되는 용어는 무엇인가. 그때 어떻게 해결하는가.
2. 뉴스에 "호재/악재" 표시가 있으면 쓰겠는가. 그 표시를 보고 사고팔 것 같은가.
3. 쉬운 설명과 영향 등급 중 어느 쪽이 더 도움이 되는가.
4. 어떤 증권사를 쓰고, 보유 종목을 직접 입력하는 것이 번거로운가.

### 0-6. 조사에서 나온 계획상 시사점

- **A안의 차별성이 약해졌다.** 대신증권이 2026-07-30에 환차손익과 매입환율 표시를 이미 넣었다(R2). 우리가 A안으로 가려면 "주가 효과와 환율 효과 분리", "이상 알림", "AI 요약"처럼 증권사 화면에 없는 부분이 차별점이 되어야 한다. 다만 다른 증권사 화면과 분리 표시 여부는 아직 확인하지 못했다.
- **B안은 주제 예시와 가깝지만 현장 근거가 약하다.** 기업 쪽에서 찾은 자료(R3, R4)는 거시·민감도 분석이고, 건별 점검 업무를 직접 다룬 자료는 아직 못 찾았다. 현직자 인터뷰가 필요하다.
- **데이터 준비가 가능한지부터 확인해야 한다.** ECOS API를 직접 열어 보기 전에는 환율 데이터 연동 가능 여부를 단정하지 않는다.
- 세금 계산은 근거가 충돌하므로 MVP 범위에서 뺀다.
- **증권사 API 연동은 모든 사용자에게 보장할 수 없다.** 해외주식 잔고 조회가 명시된 곳은 KIS뿐이고(R9, R10), KB는 미확인(R8)이다. 보유 종목 직접 입력·CSV 업로드를 기본으로 두고 API는 선택 연동으로 한다.
- **보유 종목 조회가 환율을 주는지 모르므로 환율 API(ECOS 등)는 따로 연동하는 것을 기본으로 한다.**
- **호재/악재 등급은 규칙으로 정하고 AI는 설명만 한다.** 개별 종목의 매매 판단으로 읽히지 않도록 표현과 안전장치를 정한다(R12, 10절).

## 2. "해외결제환차점검"의 의미

> 이 절은 팀 정리이며 외부 출처 확인 전이다. 확인된 자료는 0절을 본다.

정해진 표준 용어는 아니며, 아래와 같이 풀어 읽는다.

- **해외결제**: 외화로 대금을 치르거나 받는 일
- **환차**: 환율 변동으로 생기는 차액(환차손익)
- **점검**: 그 차액이 장부에 맞게 반영됐는지 확인하는 일

LS 계열사가 수출입 제조 기업이라는 점을 고려하면, 기업 재무·회계 업무로 해석하는 것이 가장 자연스럽다.

### 업무 배경

해외 거래처와 외화로 거래할 때 거래일 환율과 실제 결제일 환율이 다르면 **외환차손익**이 생긴다. 결산 때는 아직 결제되지 않은 외화 채권·채무를 결산일 환율로 다시 평가하는 **외화환산손익**도 발생한다. 담당자는 이 금액들이 장부에 맞게 기록됐는지 건별로 확인해야 한다.

### 점검에서 하는 일

- 결제 건마다 적용된 환율이 맞는지 확인(기준 환율, 적용일)
- 거래일·결제일 환율로 환차손익을 재계산해 장부 금액과 비교
- 불일치와 이상치(금액이 크게 튀는 건, 환율 누락 등)를 찾아 리스트업
- 결산 시 미결제 외화 잔액의 환산 평가 확인

현재는 엑셀과 ERP 데이터를 사람이 대조하는 반복 업무가 많아 자동화 가치가 있다. (추측, 0-4 참고)

### 개인 카드 맥락에서의 해석

해외 카드 결제에서는 승인일과 청구(매입)일의 환율 차이로 승인 금액과 청구 금액이 달라질 수 있다. 해외 수수료, DCC(현지 통화 대신 원화로 결제) 추가 비용과 함께 보기도 한다. (DCC 수수료 3~8%는 R5 참고. 승인일/청구일 환율 적용 방식은 미확인)

## 3. 기획 접근 방식

기획 문서가 곧 AI에게 주는 설계도가 되므로 아래 순서로 진행한다.

0. **리서치**: 직접 검색 + Claude 웹 조사 → 이 문서 0절에 모음 (출처, 확인 여부 표시)
1. **문제 정의**: 지금 누가 어떻게 하고, 어디서 시간이 걸리고 실수가 나는가
2. **사용자와 목표**: 주 사용자와 성공 기준(숫자)
3. **유저 저니**: 핵심 경로와 막히는 상황·복구 방법
4. **기능 범위(MVP)**: 필수 기능과 여유 시 추가할 기능 구분
5. **정보구조(IA)와 화면 목록**: 화면 ID, 이름, 이동 관계
6. **데이터와 계산 규칙**: 사용 환율, 손익 계산식, 샘플 데이터 열 구성

| 환율 | 한국은행 ECOS API, 서울외국환중개 매매기준율 | 일별 통화별 환율 | 미확인 (0-3 참고) |
| 기업 재무·공시 | 금융감독원 DART 오픈API | 재무제표, 공시 | 미확인 |
| 무역 통계 | 관세청, 한국무역협회 | 품목·국가별 수출입 | 미확인 |
| 금리·물가 | ECOS | 기준금리, 시장금리, 소비자물가 | 미확인 |
| 주식·ETF 시세 | 공개 시세 API (후보 미정) | A안의 주가 효과 계산 | 후보 조사 필요 |
| 증권사 Open API | 한국투자증권(KIS), KB증권 등 | 보유 종목 조회(선택 연동) | KIS 해외잔고 호출 방법만 확인(R9), KB 미확인(R8) |
| 보유 종목 입력 | 직접 입력 또는 CSV 업로드 | 기본 입력 방식 | 열 구성 설계 필요(종목, 수량, 매수가, 매수일) |
| 뉴스·공시 | 뉴스 API, DART 등 | AI 해설과 영향 등급의 재료 | 미조사 (0-3 참고) |
| 거래·결제 내역 | 직접 제작한 가상 샘플 | 점검 기능 시연 | 제작 필요 |

### 가상 결제 데이터 구성(안)

- 열: 거래일, 통화, 외화금액, 적용환율, 결제일, 장부금액
- 일부 건에 의도적으로 오류를 심어 점검 기능을 시연(환율 오적용, 중복, 금액 불일치 등)

### 방향 결정 시 고려할 점

- 개인용 vs 기업용
- 계산 중심(정답 있음) vs 판단 중심 — 환율 예측처럼 정답이 없는 영역은 피함
- 사후 점검(범위 작음) vs 사전 대응(확장 기능)
- AI의 역할은 이상 사유 설명과 리포트 생성에 두고, 이상 여부는 규칙으로 판단
- 발표 전에 "이 숫자가 맞다"를 증명할 수 있도록 계산 규칙을 먼저 문서로 확정

## 6. 현재 관심 후보 5개와 비교

관심 후보:

1. 공시·뉴스 모니터링
2. 기업 재무 모니터링
3. 내 소비·구독 모니터링
4. 포트폴리오 이탈 모니터링
5. 환차 기반 모니터링

| 후보 | 데이터 구하기 | 난이도 | 주제 연결 | 시연 효과 |
|---|---|---|---|---|
| 1. 공시·뉴스 | DART 공개 API | 중 | 약함 | 높음 |
| 2. 기업 재무 | DART 공개 API | 중하 | 보통 | 보통 |
| 3. 소비·구독 | 샘플 데이터 직접 제작 | 하 | 약함 | 높음 |
| 4. 포트폴리오 이탈 | 가격 데이터 | 중 | 약함 | 높음 |
| 5. 환차 | ECOS 환율 + 샘플 | 중하 | 강함 | 중상 |

### 5번(환차 기반)의 세부 후보

- **환차손익 이상 모니터링**: 결제 건별 환차손익을 계산해 장부와 다르거나 평소보다 큰 건 탐지(주제 예시에 가장 가까움)
- **환노출(환리스크) 모니터링**: 받을 외화와 줄 외화를 모아 환율 1% 변동 시 손익 변화를 표시(기업 재무팀용)
- **결제 시점 모니터링**: 결제 예정일 전에 유리한 환율 구간이 오면 알림
- **해외결제 비용 모니터링**: 환율 변동과 수수료로 더 낸 금액 추적(3번과 결합 용이)

### 합쳐볼 만한 조합

- **1+2 → 기업 모니터링**: 재무 지표 추세와 새 공시·뉴스를 한 화면에서 보고 AI가 변화를 요약. 기업 하나(예: LS 계열사)를 사례로 활용
- **3+5 → 해외결제·구독 모니터링**: 해외 결제와 구독 지출을 잡고 환율로 인한 추가 금액까지 표시. 개인용이라 이해가 쉽고 환차 주제를 살림

### 환차 모니터링 두 방향 비교 (팀 논의용)

같은 "환차손익 이상 모니터링"이라도 사용자와 데이터가 다르다. 팀 논의로 하나를 정한다.

| | A안: 개인 해외자산 환차손익 | B안: 기업 결제 건별 환차 점검 |
|---|---|---|
| 한 줄 | 해외주식·ETF 수익을 주가 효과와 환율 효과로 분해하고, 환율 영향이 이상하게 크면 알림 | 외화 결제 건의 환차손익을 재계산해 장부 금액과 비교, 불일치·이상치 탐지 |
| 주 사용자 | 해외주식·ETF 보유자(20~30대 가정) | 수출입 기업 재무·회계 담당자 |
| 입력 데이터 | 보유 종목, 수량, 매수가, 매수일 | 거래일, 통화, 외화금액, 적용환율, 결제일, 장부금액 |
| 외부 데이터 | 환율 API + 주식·ETF 시세 API | 환율 API |
| 이상 판단 규칙(예) | 환율 효과 비중이 기준 초과, 환율 변동폭이 기준 초과 | 재계산 금액과 장부 금액 차이가 허용오차 초과, 환율 누락, 중복 건 |
| AI 역할 | 변동 원인 요약, 주간 리포트 | 이상 사유 설명, 점검 리포트 |
| 이미 있는 대안 | 증권사 앱의 환차손익 표시(대신증권, R2) | 엑셀·ERP 수작업 대조(추측, 확인 필요) |
| 주제 예시와 연결 | 보통 | 강함 |
| 현장 근거 상태 | 일부 확인(R1, R2) | 약함(R3, R4는 거시·민감도 자료). 현직자 인터뷰 필요 |
| 데이터 | 시세·환율 실데이터 가능성 있음(ECOS 미확인) | 오류를 심은 가상 데이터 필수 |

## 7. 후보 선정 기준

1. 팀이 가장 설명하고 싶은 문제가 무엇인가
2. 주제 예시(환차)와 얼마나 이어지는가
3. 데이터를 구할 수 있는가(DART, ECOS는 무료 API 존재 — 접근 방법은 아직 직접 확인 전)
4. 이미 있는 대안과 어떻게 다른가 (0-6 참고)

**잠정 추천**: 5번(환차)을 중심에 두고, 1+2의 기업 데이터 또는 3번의 개인 소비 시나리오 중 하나를 결합. 개인 쪽으로 가면 증권사 화면에 없는 기능(주가·환율 효과 분리, 이상 알림, AI 요약)을 차별점으로 둔다.

## 10. 2026-10-23 방향 업데이트 (논의 반영)

> 대화로 정리한 현재 방향이며 팀 합의 전 초안이다. 팀이 확정하면 "확정"으로 표시한다. A안(개인 해외자산)과 B안(기업 결제 점검) 중 개인 쪽으로 기운 상태이고, B안을 접을지는 팀 논의로 정한다.

### 10-1. 컨셉

증권·환율·뉴스 정보를 일반인이 알아듣기 어렵다는 문제에서 출발한다(0-4의 팀 가설). 정보를 쉬운 말로 풀어주고, 그것이 내 보유자산에 어떤 영향을 줄 수 있는지 보여주는 AI 모니터링 서비스다.

### 10-2. 사용 범위

- 사용자: 팀원과 같은 강의를 듣는 수강생 정도
- 외부 배포나 서비스 운영은 계획하지 않음
- 단, 친구가 실제 돈으로 참고할 수 있으므로 안전장치는 처음부터 넣는다(10-5)

### 10-3. 핵심 기능(안)

1. 보유 종목을 직접 입력하거나 CSV로 올린다. 증권사 API 연동은 선택 기능이다.
2. 환율 변화가 내 해외자산 원화 평가액에 준 영향을 계산한다. 규칙으로 계산하는 부분이며 AI 추측이 아니다.
3. 뉴스·환율 등 정보를 쉬운 말로 설명한다.
4. 정보마다 영향 등급을 거칠게 붙인다(10-4).
5. 요약 리포트를 낸다.

### 10-4. 영향 등급(7단계) 초안

등급은 다음 일곱 단계로 제안되었다. 기준은 아직 정해지지 않았다.

- 강악재
- 악재
- 약악재
- 영향 없음 (대부분의 뉴스는 여기로 분류해 거른다)
- 약호재
- 호재
- 강호재

설계 원칙:

- 등급은 규칙표로 정하고 AI는 그 이유를 설명한다.
- 종목 평가가 아니라 "어떤 요인이 내 자산에 유리/불리할 수 있는가"의 관점으로 표현한다.
- 출처와 불확실성을 같이 표시한다.
- 규칙표 예시(미정): 환율 변동폭 몇 %부터 약/보통/강으로 가를지, 공시 유형별 기본 등급을 어떻게 둘지

### 10-5. 안전장치

- 화면에 "참고용이며 투자 권유가 아님" 문구와 근거 출처를 항상 표시
- 매수·매도·비중 조절을 권하는 문구를 쓰지 않음
- 확실하지 않으면 모른다고 표시
- 앱키·계좌번호 등 비밀 값은 `.env`에 두고 깃에 올리지 않음(`.gitignore`)
- 실제 공개나 운영을 고민하게 되면 그때 전문가 확인

### 10-6. 법·규제 메모 (R12 기준)

- 매매판단(투자판단)은 종목, 취득·처분, 방법·수량·가격·시기 등에 대한 판단이다.
- 정보 제공 자체가 곧바로 투자자문이 되는 것은 아니며, 핵심 기준은 "개별성"(특정 개인에게 맞춘 조언인가)이다.
- 보유 종목에 맞춰 방향·강도 등급을 붙이는 것은 개별성과 종목 특정성이 생기는 쪽이라 위험 부담이 커진다.
- 소규모 시연이라 위험은 작지만, 읽은 자료에 규모나 무료 여부에 따라 면제된다는 내용은 없다. 단정하지 않고 강사·멘토에게 문의한다.
- 이 메모는 법률 자문이 아니다.

### 10-7. 결정이 필요한 것

- 이 방향을 팀이 확정하는지, B안을 접는지
- 등급 규칙표 (환율, 뉴스·공시 기준)
- 보유 종목 입력 방식(직접 입력 / CSV / 증권사 API)
- 증권사 API를 붙인다면 어느 증권사부터(팀원들이 쓰는 곳 기준)
- 뉴스·공시 데이터 소스(미조사)
- AI가 어디까지 말하게 할지
